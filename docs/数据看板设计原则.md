# 数据看板设计原则

本文整理自线索数据看板中已确认的展示和交互要求，供 `work` 目录下其他数据看板设计时参考。通用交互原则可按场景复用；具体指标口径、关联字段和数据范围应以对应项目及业务知识库的最新规则为准。

- 以数据工作为中心：标题、筛选和容器保持紧凑，优先让用户看到指标与明细；沿用浅色背景、克制的操作色和细分隔线，避免过大的圆角与无意义装饰。
- 指标数字使用等宽数字便于比较；表格中的数值靠右对齐，保证行列、排序和宽表局部滚动清晰可用。操作控件的高度、圆角、焦点及状态反馈保持一致。
- 使用语义明确的文字色、表面色、边界色和操作色；主要操作使用实色按钮，更新、导出等次要操作使用中性按钮，悬停、焦点和禁用状态应易于分辨。文字与背景的对比度需要实际测量。
- 线索看板采用暖沙色背景、浅色内容面和深绿色操作色；分类和趋势图仍需保持可辨识，不因统一配色而牺牲数据区分。

## 1. 筛选和日期

- 多选筛选项应提供全选和清空；选项较多时提供搜索，页面提供重置。搜索后“全选搜索结果”只选中当前匹配项，并保留其他已选项；无匹配结果时禁用全选。
- 多选后直接展示已选名称，让用户不展开也能知道选了什么。空间不足时展示前面的内容并用省略号截断；展开后能查看全部已选项。
- 同一字段选择多个值时，按任一选中值匹配；不同字段之间共同生效。未选择某个字段表示不限制该字段。
- 全选列出的选项不自动包含该字段的空值；清空选择表示不限制该字段。筛选组件保持简洁，不在下拉框内附加说明文案。
- 日期选择器的星期、日期和操作按钮应完整可见、可点击，桌面和窄屏都要检查，避免表格等全局样式影响日期组件。
- 筛选条件应用后，总览和明细应反映同一筛选范围。需要点击按钮应用时，以已应用的结果为准。
- 需要保留筛选的看板应在同一浏览器重新打开时恢复上次筛选；若选择后还需点击按钮应用，分别保存未应用的选择和已应用条件，避免控件与结果对应错乱。重置筛选也应同步清除已保存条件，无法保存时应提示用户。
- 筛选选项只展示业务范围内的数据，并按业务习惯排列；展示范围应同时作用于总览、明细和导出。具体纳入范围由项目确定，不直接套用其他看板的学部或分类规则。
- 使用可维护的映射表时，可将映射结果作为筛选项和明细维度。未命中如何归类、空值如何处理以及映射冲突时如何提示，应按项目规则明确；映射表更新后，相关查询和导出应读取最新有效映射。

## 2. 明细表和导出

- 设计数据看板时，把多选、导出和明细字段选择作为基础功能考虑。
- 默认展示字段由看板的主要查看任务确定，不必展示全部字段；允许用户按需勾选维度和指标。线索看板默认展示日期、学部、批次类型、例子量、接通转化率、有课例产、单例子结算成本和北A，按前三个维度汇总。
- 字段选择入口可折叠，并展示已选字段数量；展开后清楚区分已选和未选字段。
- 勾选的维度决定数据的分组粒度；未勾选的维度不再拆分行。指标勾选只控制显示。比率和加权指标按各组的分子、分母重新计算，不直接平均展示值。筛选、汇总、排序和分页的先后关系应明确。
- 分类字段可使用文字配合低饱和色标签区分，颜色不替代文字；表头排序图标应区分当前方向，并保留可访问的排序状态。
- 默认排序应贴合查看任务，并在表头标明排序方向；支持用户手动调整排序。日期类明细可优先展示最新日期，同一日期内的业务类别按约定顺序排列；缺失值的位置应明确。默认排序和手动排序都应在分页前生效，导出沿用当前顺序。
- 涉及多来源指标时，按各指标确认的来源及公式分别计算；例如线索看板接通转化率使用线索表，经营利润相关指标使用经营表，不混用来源的分子或分母。
- 支持导出数据。导出应使用当前已应用的筛选和排序，覆盖当前筛选与维度下的全部结果，而不只导出当前页；导出字段与用户勾选的展示字段一致。
- 页面总览、明细和导出中，同一指标使用一致的展示精度。导出保留可计算的数值，展示舍入不改变底层计算结果。
- 明细表过宽时，在表格区域内横向滚动，避免整个页面横向溢出；筛选、字段选择和导出入口也要检查窄屏显示。

## 趋势图

- 与表格共用已应用筛选范围，按图表注明的日期与分类粒度重算指标，不受表格分页影响；缺失值不补零、不跨缺失日期连线。
- 不同单位的指标分别绘图，线条以图例标识分类；数据点展示口径与表格一致。日期较多时使用图表区域内横向滚动，避免整页溢出。

## 3. 指标展示精度

以下为当前业务知识库中已确认的规则；引用前应核对指标定义及知识库是否有更新：

| 指标 | 展示规则 | 示例 |
| --- | --- | --- |
| 接通转率 / 接通转化率 | 百分比，保留两位小数 | `0.05%` |
| 有课例产 | 保留整数 | `58` |
| 单例子结算成本 | 保留整数 | `93` |
| 北A | 按比值保留一位小数，不加百分号 | `1.1` |

数值先按业务口径计算，最后才按上述精度展示。不能为了展示先舍入参与汇总的数值；缺失或无法计算的值不应当作零。

## 4. 状态与文案

- 数据来源路径固定、由用户在本地维护时，可在页面标题右侧提供“更新数据”按钮，点击直接读取已保存的底表，避免重复选择文件。操作入口沿用页面已有按钮样式，桌面和窄屏均应清晰可用。
- 更新过程提供进行中、成功和失败反馈，避免重复提交。读取失败、缺少必要字段或映射冲突时，应指出可定位的问题；涉及多份需要一起更新的来源时，先完成校验，再统一替换，避免只更新部分数据。多余字段按项目规则忽略。
- 状态名称应让用户直接知道发生了什么、需要核对哪里。例如：经营表有记录但线索表没有匹配记录时显示“线索表未找到”；反之显示“经营表未找到”。
- 区分“未找到匹配记录”和“关联字段缺失”。字段缺失时保留来源信息，便于定位需要补全的表。
- “已匹配”只说明按项目约定的关联字段找到了对应记录，不能据此认定来源范围、统计口径或指标值一定一致。
- 去掉对当前操作没有帮助的说明和页脚文案；保留错误原因、必要后果和下一步等真正帮助用户完成任务的信息。

## 5. 交付前检查

- 实际操作日期选择、多选、搜索、清空、重置、字段勾选和导出，检查空值、长名称及较小百分比的展示。
- 检查不同窗口宽度下是否有文字裁切、控件遮挡或意外的整页横向滚动；表格的局部横向滚动应可用。
- 核对维度切换后的聚合及比率计算，并检查导出的行数、字段、筛选范围和显示精度，与当前页面结果一致；确认导出不是只包含当前页。
- 核对业务范围、默认排序和手动排序在页面与导出中的一致性；使用映射表时，验证新增或修改映射、未命中及冲突的处理。
- 对有更新入口的看板，实际验证保存底表后的更新流程及失败反馈，确认失败时原数据保持可用。
